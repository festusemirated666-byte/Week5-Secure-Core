# Control Register

| ID | Policy Statement | Technical Control | Verification Method | Evidence |
|---|---|---|---|---|
| CTRL-001 | HIGH security findings must block insecure changes from progressing through the pipeline. | Python vulnerability scanner returns exit code 1 when a HIGH finding is present. GitHub Actions runs the scanner without `continue-on-error` or `|| true`. | Run the vulnerable fixture locally and inspect the failed GitHub Actions workflow. | `evidence/local-failed-scan.png` and `evidence/failed-pipeline.png` |
| CTRL-002 | Fixed code must pass the security gate. | Scanner returns exit code 0 when no HIGH finding is present. | Run the fixed fixture locally and inspect the successful GitHub Actions workflow. | `evidence/local-passed-scan.png` and `evidence/passed-pipeline.png` |
| CTRL-003 | Source code must not contain real passwords, API keys, private keys, live tokens, or database credentials. | Secret-hygiene review and scanner checks for secret-like patterns. | Inspect repository contents, Git status, staged files, and run the documented secret-hygiene check before submission. | `evidence/secret-hygiene-check.md` |
| CTRL-004 | Application input must be validated before being used by application logic. | Server-side input validation in `training-fixtures/fixed.js`. | Run the scanner against the fixed fixture and inspect the remediation code. | `training-fixtures/fixed.js` and `evidence/local-passed-scan.png` |
| CTRL-005 | SQL queries must not directly interpolate untrusted request input. | Parameterized SQL query using a placeholder and bound parameter. | Compare `vulnerable.js` with `fixed.js` and run the scanner against both fixtures. | `training-fixtures/vulnerable.js`, `training-fixtures/fixed.js`, `evidence/local-failed-scan.png`, and `evidence/local-passed-scan.png` |
| CTRL-006 | GitHub Actions must automatically enforce the security scan. | `.github/workflows/security-scan.yml` executes the vulnerability scanner on pushes and pull requests targeting `main`. | Inspect the workflow and review both failed and successful workflow runs. | `.github/workflows/security-scan.yml`, `evidence/failed-pipeline.png`, and `evidence/passed-pipeline.png` |
| CTRL-007 | Repository access must follow least-privilege principles. | GitHub Actions workflow uses `permissions: contents: read`. | Inspect the workflow permissions and repository settings. | `.github/workflows/security-scan.yml` |
| CTRL-008 | Security testing must remain within authorized classroom scope. | Scanner targets controlled training fixtures in the repository. | Review scanner commands, fixture files, and repository contents before submission. | `README.md`, `training-fixtures/`, and `evidence/secret-hygiene-check.md` |
| CTRL-009 | Suspected credential exposure must be handled as a security incident. | Incident-response requirements in the Security Policy. | Review the policy and confirm the repository contains no real credentials. | `security-policy.md` and `evidence/secret-hygiene-check.md` |
| CTRL-010 | Security requirements must be reviewed and improved through peer feedback. | Peer-review record documents reviewer feedback and resulting implementation or policy change. | Review `peer-review.md` and confirm the final policy or implementation reflects the accepted improvement. | `peer-review.md` |
